Nearly four in ten derived leaks go unflagged — until you add one sentence.

Give a language model a list of column names and a target and ask which columns could not honestly be known at prediction time. It reliably finds the ones that arrive too late — 96% of them — and catches only 62% of the ones the label was computed from. The blind spot is definitional, not statistical, and one clause in the prompt closes almost all of it.

The sentence — this is the whole intervention

“A column is also inadmissible if the target was computed from it — regardless of when it was recorded.”

Why this is a prompt result

The model, the schema and the scoring are held fixed. The only thing that changes between C1 and C6 is one added sentence, and the comparison is made on the exact cells answered under both — matched on dataset and shuffle, never pooled.

Where the gain is, and isn't

Measured in F1 the lift concentrates in the weaker models. For the three strongest, a cluster bootstrap over datasets is consistent with no effect at all. The honest claim is about the subtype it repairs, not a headline score.

C9 is the counterweight

C9 states the same criterion without mentioning time. It rescues one model by +0.190 F1 and costs another 0.061. No wording is uniformly better — prompt interventions here need per-deployment validation, which nothing currently provides.

Not memorisation

Rename every column to a meaning-preserving alias and both frontier models score marginally better. A keyword rule fitted to these leaks scores 0.394 here and 0.000 on the held-out set — leaked column names share no transferable vocabulary.
