LeakLadder — a four-pass consensus workflow for feature-level target leakage

Measured against a single-prompt baseline on 2,548 column-judgments · 15 datasets · 5 models · 264 documented leaks. Every node's query is a prompt variant that was run and scored, not a proposal.

human input required LLM call — structured JSON out deterministic code, no model output
1 · Intake
N1Human
Schema + target
Column names and the column to be predicted. No values are sent — leakage is a property of meaning, not of numbers, so the model never sees data.
N2Human — cannot be automated
Prediction point
The moment the model will be asked to answer, in one sentence. This is the irreducible human input: the same column is admissible under one prediction point and not another, and nothing in the file says which one you mean.
the same schema is sent to four differently-worded queries, in parallel
2 · Four passes
P1LLM
Bare judgment
Which columns could not honestly be known at the prediction point? Return {name, verdict, confidence, reason} per column.
The unprimed baseline. Catches 96% of late-arriving columns on its own.

3 · Merge
M1Deterministic — no model
Consensus router
Counts how many of the four passes flagged each column and routes on that count alone. Deliberately not an LLM: an adjudicating model would add a fifth opinion where what is needed is an audit trail. Union was tried and rejected — flagging on any single pass drops precision 0.729 → 0.583, because four chances to flag is four chances to flag wrongly.

170 cols · 6.7% of the table
34 more leaks live here. The passes disagreed, so a person decides — and the queue is small enough that a person actually can.
Keep · 0 of 4 flag
2,124 cols
17 leaks missed by every pass — 6.4%. Reported, not hidden: this is the workflow's floor, not its ceiling.
Result vs a single prompt F1 0.800 → 0.822, precision 0.729 → 0.839. But F1 is not the point: a single call returns one flat list with no signal about which of its own flags to trust. 93.6% of all leaks reach a human, at a 6.7% review burden.
What this workflow does not do It does not find undocumented leaks, and it does not remove the expert. Its output is a prioritised queue, and the 17 columns no pass flagged are exactly the failure a user must be told about rather than sold past.
